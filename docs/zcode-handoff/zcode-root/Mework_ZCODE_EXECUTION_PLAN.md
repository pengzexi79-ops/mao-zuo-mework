# 猫作 / Mework 全环境真实可用实施指令

> 文档用途：供 ZCode 按阶段执行，不是产品介绍。
> 目标项目：`<legacy-workspace>\ai-douyin-mixcut`
> 主运行方式：Windows 本地优先，Spring Boot + Vue + MySQL + FFmpeg。
> 生成日期：2026-08-22

## 0. 总目标与完成定义

把项目中已经声明的能力，分成“本地必备能力”和“外部服务能力”，逐项做到：

1. 能力中心状态准确：`ready` 只代表真实探测成功，`detected_only`、`external`、`missing` 不得伪装成已完成。
2. 从真实用户入口完成闭环：配置、执行、任务状态、错误提示、产物入库、质量检查、重试和日志都能工作。
3. 本机重启后可恢复：数据库、素材、任务、输出和配置不丢失；运行中的任务要能被标记为可恢复或明确失败。
4. 外部服务可替换：AI Provider 和素材源使用适配器，不把某一家供应商写死在业务流程中。
5. 所有密钥只存在服务端配置或加密数据库，不进入前端构建产物、日志、错误信息或提交记录。
6. 没有账号、额度、授权或硬件时，系统要明确告诉用户缺什么，而不是返回假成功。
7. 每个阶段完成后都能独立验收，失败时保留诊断信息，不破坏已完成阶段。

“全部真实可用”不等于自动拥有第三方账号、额度、素材版权或 NVIDIA 硬件。此类外部前置条件必须通过配置检查和人工授权完成。

## 1. 当前基线与已知缺口

### 1.1 已有主链路

- 前端：Vue 3、Vue Router、Element Plus、Axios、Vite。
- 后端：Spring Boot 3.3.2、Java 17、JPA、MyBatis-Plus、MySQL Connector/J。
- 本地媒体：FFmpeg、FFprobe、ImageMagick、Python 工具链。
- 已有业务域：素材库、抓取、AI 设置、AI 创作、项目、工作流、Studio 出片、成片库、编辑器、质检、能力中心。
- 已有外部适配：OpenAI-compatible、Anthropic、Gemini、Pixabay、Pexels、Freesound、Wikimedia Commons、Internet Archive。
- 已有本地能力：yt-dlp、you-get、gallery-dl、whisper.cpp/faster-whisper、RapidOCR、OpenCV、Edge-TTS、可选 ChatTTS、Demucs、Auto-Editor、rembg。

### 1.2 必须先处理的真实问题

- `APP_ALLOW_LOGIN_CRAWL` 与 `application.yml` 的固定 `allow-login-crawl: false` 不一致。默认保持关闭，但必须明确支持配置覆盖，并在 UI 显示风险和当前值。
- `APP_IMAGEMAGICK_PATH` 文档声明与实际路径解析不一致。统一配置名、绑定和能力探测。
- `capabilities.json` 的设计声明不能直接当运行时可用。能力中心必须区分声明、探测、业务冒烟成功。
- AI 媒体生成目前缺成本估算、预算/额度保护和账单同步。至少补调用前确认、每次用量记录、可选预算上限和失败可追踪。
- AI 生成任务和媒体工具任务的持久化、重启恢复要核实；内存状态不能被 UI 误认为永久任务状态。
- Pixabay、Pexels、Freesound 等 Key 的“已设置”不等于“可调用”。必须实际做轻量连通性和配额错误分类。
- HyperFrames、Remotion、Openverse OAuth、部分素材站点目前只是目录/入口，不能写成已接入主链路。要么正式接入并验收，要么明确标为资料项。
- 版本号和文档口径不一致：Maven `1.0.0`、产品版本 `2.2.101`、文档仍有旧版本。统一发布版本和能力清单版本。
- 根目录可能存在历史 `.env.backup-*`、`.env.safe-*`、`.env.tokenbackup-*`。执行时不得打印、上传或提交这些文件。

## 2. 执行规则

### 2.1 每次执行前

1. 读取本文件和项目现有 `README.md`、`docs/ARCHITECTURE.md`、`PACKAGING.md`。
2. 执行 `git status` 或等价变更检查。项目不是标准 Git 仓库时，建立文件级变更清单，不覆盖用户已有修改。
3. 检查端口、Java、Maven、Node/npm、Python、MySQL、FFmpeg、FFprobe 的版本；只报告是否存在，不打印密钥。
4. 先做只读诊断，再做最小修改。除非任务明确要求，不删除数据库、素材、输出、历史配置或备份文件。
5. 任何联网安装、下载模型、调用付费 API 前，先在执行记录中列出目标、版本、可能费用和回滚方式。

### 2.2 统一状态模型

每个能力必须至少有以下状态：

- `declared`：代码或能力清单声明存在。
- `detected`：本机/配置可检测到。
- `wired`：真实业务入口已连接。
- `smoke_passed`：最小真实样例执行成功。
- `ready`：满足产品运行前置条件并通过最近一次验收。
- `blocked`：缺依赖、Key、额度、授权、模型或硬件。
- `degraded`：主工具失败但有明确回退。

UI、API 和日志不得把 `declared` 或 `detected` 直接显示为 `ready`。

### 2.3 外部服务和版权边界

- 只使用公开、授权、符合供应商条款的素材；不绕过登录、DRM、验证码或访问控制。
- 不读取浏览器 Cookie、密码或用户登录态。
- 保留 URL、来源、许可、抓取时间和归属信息，导入前显示许可风险。
- 对 SSRF、私网、回环地址和危险重定向保持现有防护。
- AI Provider 只允许 HTTPS；API Key 不写前端、不写日志、不回显。

## 3. 阶段总览

| 阶段 | 名称 | 结果 |
|---|---|---|
| P0 | 基线、配置和安全校准 | 可重复诊断，状态不造假，配置一致 |
| P1 | Windows 本地运行时完整化 | 新机器可按文档安装并通过环境验收 |
| P2 | 核心剪辑闭环 | 素材到成片、质检、重试、重启恢复可用 |
| P3 | 本地 AI 媒体能力 | ASR/OCR/TTS/分离/抠图/去静音全部可验收 |
| P4 | 外部素材源与文本 AI | 每个 Provider 可配置、测试、路由、降级 |
| P5 | AI 图片/视频/语音生成 | 付费调用有确认、预算、任务持久化和产物闭环 |
| P6 | 编辑、交付和可观测性 | 编辑器、输出版本、质量门禁、日志和诊断完善 |
| P7 | 发布验收和运维 | 安装包、升级、备份、恢复、最终能力矩阵 |

依赖顺序：`P0 -> P1 -> P2 -> P3/P4 -> P5 -> P6 -> P7`。P3 和 P4 可以并行，但都必须先完成 P2 的核心闭环。

## P0：基线、配置和安全校准

### 目标

建立可信的起点，先解决“看起来接入但实际不可用”的问题。

### 执行任务

1. 扫描并记录当前项目版本、目录、端口、依赖、能力清单和环境变量名。
2. 统一 `application.yml`、`AppProps.java`、`.env.example`、启动脚本和文档中的配置名。
3. 修复 `APP_ALLOW_LOGIN_CRAWL` 绑定：默认仍为 `false`，只有显式配置才允许打开；开启时 UI 必须显示高风险警告。
4. 修复 ImageMagick 路径配置，允许显式路径、便携路径和 PATH 三种来源，并返回实际命令和版本。
5. 为每个能力增加 `declared/detected/wired/smoke/ready/blocked` 的结构化字段，保留失败原因和建议动作。
6. 为 AI Provider、素材 API、模型、外部工具做健康检查，但禁止健康检查触发付费生成或大文件下载。
7. 检查所有日志和异常响应，脱敏 API Key、Authorization、数据库密码、下载签名 URL。
8. 统一版本来源，至少让 Maven、前端构建、产品信息、发布记录和能力报告显示同一产品版本。
9. 编写 `docs/ENVIRONMENT_MATRIX.md`，列出必需、可选、付费、硬件相关依赖。

### 验收

- 新增或更新环境检查接口，能准确显示每项能力的状态、版本、路径、失败原因和修复建议。
- 使用错误 Key、空 Key、超时、429、401、403 时，UI 能区分“未配置、认证失败、额度/限流、网络失败”。
- 执行日志中搜索不到真实密钥。
- 配置覆盖测试通过：修改 `.env` 后重启，运行时读取值改变；默认安全值仍有效。
- `mvn test` 和前端构建通过；不删除原有测试。

## P1：Windows 本地运行时完整化

### 目标

做到在一台干净 Windows 机器上，按安装说明准备运行时，并通过统一验收。

### 执行任务

1. 固定并检查 Java 17、Maven、Node/npm、Python、MySQL 8、FFmpeg/FFprobe 版本。
2. 统一 Python 解释器策略：所有 Python 工具必须使用项目 `.venv` 或明确的 `APP_LOCAL_PYTHON`，禁止一部分走系统 Python、一部分走未知 PATH。
3. 更新 `requirements-windows.txt` 和能力清单，明确固定版本、可选版本、模型文件和磁盘空间需求。
4. 将 `setup_runtime.bat verify/repair` 做成幂等操作：重复执行不会破坏已有环境；安装失败输出可读诊断。
5. 检查便携目录、相对路径、中文路径、空格路径和权限；所有路径统一使用绝对路径或可靠解析。
6. 为 whisper.cpp、faster-whisper、Demucs、rembg、RapidOCR、OpenCV、Auto-Editor、Edge-TTS 建立逐项探测和最小样例检查。
7. 明确 GPU 加速是可选能力；若没有 NVIDIA/CUDA，不得显示为失败主流程，必须显示 CPU 模式和预计性能。
8. 增加本地磁盘、内存、临时目录和输出目录可写性检查。
9. 为 MySQL 增加启动、连接、迁移、备份和恢复检查；禁止启动脚本静默覆盖已有数据库。

### 验收

- 在干净测试目录执行安装/启动脚本，服务能启动在预期端口。
- `GET /api/system/capabilities` 返回每个依赖的真实版本和状态。
- 用 10 秒视频、1 张图片、短文本分别完成 FFmpeg、OCR、ASR、TTS、抠图、去静音和人声分离最小样例。
- 关闭某个可选工具后，能力状态变为 `blocked/degraded`，主应用仍可启动且给出回退方案。
- 启停应用两次后数据库、素材和输出目录内容一致。

## P2：核心剪辑闭环

### 目标

不依赖云端 AI，完成“导入素材 -> 分析 -> 规划 -> 渲染 -> 质检 -> 成片下载”的真实闭环。

### 执行任务

1. 使用固定测试素材集建立 fixture：横屏、竖屏、无音频、损坏文件、带原字幕、短片、长片、图片和音乐。
2. 验证素材上传、扫描、ZIP 导入、缩略图、FFprobe 元数据、角色分类、切片和索引。
3. 验证工作流/项目参数校验：时长、画幅、FPS、产品片段比例、素材缺口和非法路径。
4. 验证 `dry-run` 时间线和真实 FFmpeg 计划一致，禁止 AI 或前端直接生成任意 shell 命令。
5. 验证渲染队列：提交、排队、进度、暂停、恢复、取消、失败重试、并发上限和队列上限。
6. 验证音频混音、字幕烧录、画幅转换、片头片尾裁剪、产品片段插入和输出命名。
7. 验证 Delivery QC：黑屏、静音、音视频漂移、冻结帧、字幕同步、重复镜头和输出可播放性。
8. 验证失败回退：缺少音频、缺少字幕字体、FFmpeg 子进程超时、磁盘不足和源文件消失。
9. 验证输出入库、版本、下载、打开目录和输出目录重索引。
10. 给每个任务保存输入快照、工具版本、参数摘要、产物路径、QC 结果和错误分类。

### 验收

- 用固定 fixture 一键生成一条 30-60 秒竖屏成片。
- 成片可被 FFprobe 读取，音视频流存在且时长在容差内。
- QC 阻止明显黑屏、完全静音、严重漂移的成片进入“交付通过”。
- 强制终止后端再重启，任务状态不会永久卡在运行中；可恢复任务能继续，其他任务明确标记失败。
- 同一输入重复执行得到可追溯的独立输出版本。
- 后端已有测试全部通过，并新增至少一条端到端冒烟测试。

## P3：本地 AI 媒体能力

### 目标

把本地识别、配音和媒体处理从“代码存在”提升到每项都有真实样例和回退。

### 执行任务

1. ASR：优先 whisper.cpp，失败回退 faster-whisper；保存模型版本、语言、耗时、置信度/失败原因和转写缓存。
2. OCR：固定输入帧采样、文字框结果和原字幕风险标记；处理无文字、低清和中文场景。
3. TTS：Edge-TTS 作为网络回退，ChatTTS 作为可选本地能力；UI 显示联网状态、声音、语言和失败原因。
4. Demucs：明确 CPU/GPU 模式、模型缓存、并发和超时；输出人声/伴奏并登记来源关系。
5. Auto-Editor：先走工具链，失败回退 FFmpeg；保存剪除区间，禁止静默误删关键语音。
6. rembg：输出透明图、模型版本和原图关联；模型缺失时不给假成功。
7. OpenCV/RapidOCR：把诊断结果写入素材分析记录，供素材准入和 QC 使用。
8. 为所有模型下载增加缓存目录、哈希/版本记录、断点失败提示和磁盘空间预估。
9. 增加 CPU-only 验收集；GPU 只作为增强路径，不得成为默认依赖。

### 验收

- 每项本地能力都有一个可重复命令或 API 冒烟测试。
- 输出文件存在、格式正确、可被后续 Studio 流程消费。
- 关闭模型或断网时，系统准确显示阻塞原因；Edge-TTS 断网不应伪造音频。
- 本地能力结果可在素材详情、任务日志和成片 QC 中追溯。

## P4：外部素材源与文本 AI

### 目标

把外部服务接入做成可配置、可测试、可降级、可追踪的真实适配器。

### 执行任务

1. 为 Pixabay、Pexels、Freesound、Wikimedia、Internet Archive 分别实现：配置检查、轻量连通测试、搜索、结果标准化、下载、许可字段保存和限流错误分类。
2. API Key 只从后端读取；前端只显示掩码和状态，不回传密钥到日志或静态资源。
3. 对 401、403、429、5xx、超时、空结果、许可不合格分别处理，设置退避和并发上限。
4. 对公开页面解析源明确标为“手动/实验性”，不要把 Mixkit、toSound 等伪装为稳定 API。
5. 登录站点保持默认关闭；若未来要开启，必须单独设计授权、条款确认、Cookie 隔离和审计，不得读取用户浏览器会话。
6. AI Provider 完成 OpenAI-compatible、Anthropic、Gemini 三种协议的统一接口、超时、重试、fallback 和错误分类。
7. Provider 模型发现只生成候选；文本、视觉、图片、视频、TTS 能力必须分别显式采用和校验。
8. 为文本 AI 增加离线 fallback：没有 Provider 时脚本、标题、钩子仍能用受限模板生成，且 UI 明确“本地规则模式”。
9. 保存每次调用的 Provider、模型、用途、时间、耗时、输入/输出 token（若供应商返回）、状态和错误摘要；禁止保存完整敏感提示词或密钥。
10. 增加 mock HTTP Provider 测试，覆盖成功、超时、429、错误 JSON、fallback 和协议差异。

### 验收

- 使用测试 Key/Mock 服务能完成每种协议的连通测试、模型发现、路由和一次文本调用。
- 真实 Key 未配置时，AI 页面显示“未配置”，不会显示“已接入”。
- 外部素材搜索结果带来源和许可；不合格许可不能自动进入“可商用”集合。
- 断网或 API 限流时，任务进入可解释的 `blocked/degraded`，不会卡死或重复扣费。
- API 调用日志能查询但不泄露 Authorization、Key、完整媒体内容。

## P5：AI 图片、视频和语音生成

### 目标

把付费生成做成可控的异步任务闭环，而不是只有接口调用。

### 执行任务

1. 仅允许已启用、已测试、显式声明媒体能力的 OpenAI-compatible Provider。
2. 调用前展示供应商、模型、分辨率/时长/声音、预计计费信息（能获取则显示，不能获取则明确“以官方账单为准”）。
3. 增加用户确认、项目级预算上限、单任务上限、并发上限和每日调用上限；默认保守值。
4. 图片、视频、语音任务全部持久化：提交参数摘要、远端任务 ID、轮询状态、重试次数、下载状态、费用元数据和最终素材关联。
5. 重启后恢复轮询；远端任务已完成但本地下载失败时可以重新下载，不重复提交生成。
6. 校验下载响应的 Content-Type、大小、哈希和文件安全性；不把远端 URL 永久写成公共地址。
7. 失败时区分认证、余额/配额、模型权限、参数不支持、超时和下载失败。
8. 生成结果必须进入素材库，保留 Provider、模型、生成时间、提示词摘要和版权/商用备注。
9. 增加 mock 任务服务和一次真实低成本冒烟测试；真实付费测试必须人工确认后执行。

### 验收

- 图片、视频、语音各完成一次端到端任务并入库，或在没有付费账号时用 Mock 完成全流程。
- 刷新页面、重启后端后任务状态连续且可追溯。
- 触发预算/并发限制时，不会发出新的供应商请求。
- 用户取消任务时，若供应商支持取消则调用取消；不支持时停止轮询并说明远端任务可能继续计费。

## P6：编辑、交付和可观测性

### 目标

让用户能安全修改成片、比较版本、理解失败原因并交付。

### 执行任务

1. 验证 Editor 的时间线排序、启停、替换、插入、裁剪、音量、BGM、口播、字幕和原字幕处理。
2. 编辑器只允许受控参数，不能接受任意 FFmpeg 命令或任意本地路径。
3. 候选渲染必须先 QC；只有明确确认后才能应用到正式输出。
4. 输出版本保存父子关系、差异摘要、QC 结果、创建人/时间和可回滚信息。
5. 为任务、外部 API、下载、FFmpeg、Python 工具增加 correlation ID、阶段耗时、退出码和可读错误。
6. 增加日志轮转、大小上限、敏感字段脱敏和诊断包导出；诊断包不得包含密钥和原始媒体，除非用户明确选择。
7. 增加健康检查、就绪检查、队列深度、失败率、平均渲染耗时、磁盘空间和最近一次能力探测时间。
8. 对输出目录、素材目录、临时目录做权限和磁盘配额保护。

### 验收

- 一个输出可生成多个版本，并能查看、下载、回退到上一个通过 QC 的版本。
- 发生 FFmpeg/Python/API 失败时，用户能从任务详情知道失败阶段和下一步处理。
- 诊断包可用于复现问题，且扫描不到数据库密码、API Key、Authorization 和签名下载地址。

## P7：发布验收和运维

### 目标

形成可安装、可升级、可备份、可恢复的交付版本。

### 执行任务

1. 统一版本号并生成变更记录、依赖清单、能力矩阵和已知限制。
2. 安装包包含必需本地运行时或明确安装向导；可选模型和第三方 Key 不打包。
3. 新安装、覆盖升级、回滚、卸载保留策略分别测试；默认不删除用户素材、数据库和输出。
4. 增加数据库迁移前备份、迁移后校验和失败恢复步骤。
5. 增加素材库和配置备份/恢复，不备份明文密钥；恢复后验证加密主密钥兼容性。
6. 生产/局域网模式必须明确绑定地址、访问令牌、CORS、反向代理和端口暴露风险。默认保持本地安全配置。
7. 为核心流程建立自动化验收脚本：环境、导入、分析、渲染、QC、输出、重启恢复、AI Mock、外部源 Mock。
8. 发布前跑全量后端测试、前端构建、安装包 Smoke、端到端 fixture 测试，并保存报告。

### 最终交付物

- `docs/ENVIRONMENT_MATRIX.md`
- `docs/CAPABILITY_MATRIX.md`
- `docs/OPERATIONS.md`
- `docs/PROVIDER_SETUP.md`
- `docs/TEST_PLAN.md`
- 可重复的 `verify`、`smoke`、`backup`、`restore` 命令/脚本
- 最终能力报告：每项能力的状态、版本、前置条件、费用归属、最近验收时间和失败原因

## 4. 建议的 ZCode 执行格式

每个阶段必须按以下格式执行并回报：

```text
[阶段] Pn - 名称
[范围] 修改的文件/模块
[前置] 已满足的环境、账号、模型或授权
[变更] 实际完成的代码、配置、脚本和文档
[验证] 执行的命令、API 冒烟、测试样例
[结果] 通过 / 部分通过 / 阻塞
[阻塞] 缺什么、由谁提供、是否可能产生费用
[回滚] 如何恢复到阶段开始状态
[下一阶段] 仅列出已解除依赖的任务
```

阶段未通过时：

- 不进入依赖它的下一阶段。
- 保留失败日志和复现输入。
- 只修复当前阶段范围，不顺手重构无关模块。
- 不能用静态声明、模拟成功、假文件或手工改数据库来替代真实验收。

## 5. 第一轮立即执行顺序

ZCode 首轮只执行以下内容：

1. P0 的只读基线和变更清单。
2. P0 的配置名一致性、安全脱敏和能力状态模型设计。
3. 生成 `docs/ENVIRONMENT_MATRIX.md` 和 `docs/CAPABILITY_MATRIX.md` 初稿。
4. 运行现有后端测试和前端构建，记录基线，不修改测试结果。
5. 输出阻塞清单：缺少的本机依赖、模型、API Key、额度、账号、版权授权和硬件。
6. 用户确认阻塞清单后，再执行 P0 修复和 P1 环境改造。

不要在第一轮：

- 直接调用付费 AI 生成图片、视频或语音。
- 下载需要登录的站点内容。
- 删除或重建 MySQL 数据库。
- 删除素材、输出、备份或历史配置。
- 把 HyperFrames、Remotion、Openverse 等资料项标成已完成。
- 把 API Key 写入前端、代码、日志、截图或文档。

## 6. 最终判定标准

只有同时满足以下条件，才可以对外说“已打通”：

- P0、P1、P2、P6、P7 通过。
- 每个本地能力至少有一次真实 fixture 冒烟通过。
- 每个外部 Provider 都有真实连通测试，未配置的 Provider 显示阻塞而非成功。
- AI 付费能力有预算、确认、持久化任务、重启恢复和费用记录。
- 核心成片通过播放性和交付 QC。
- 全量测试、构建、安装包 Smoke 和重启恢复测试通过。
- `CAPABILITY_MATRIX.md` 中没有“只声明未验证”的能力被标为 `ready`。

最终报告必须明确分为：

1. 已真实可用；
2. 已接入但需要用户账号/Key/额度/授权；
3. 已接入但需要本机硬件或模型；
4. 有回退但主能力不可用；
5. 仅展示/预留，尚未接入；
6. 明确不实现的能力及原因。
