## 目标

1. 完全移除“无限画布”产品入口和不可达 UI，避免继续占用导航、Studio 快捷入口、教程和 AI 创作交接逻辑。
2. 保留共享的 AI 图片、视频、配音、素材库、编辑器和任务接口，不误删通用能力。
3. 生成一份可直接转发给新对话/新开发智能体的项目交接 Markdown 文件，包含产品定位、技术架构、功能地图、开发历史、版本/启动状态、构建测试方式、安全边界、已完成事项、遗留风险和下一步。

## 一、无限画布删除范围

### 删除入口

- 从 `frontend/src/router.js` 删除 `/infinite-canvas` 页面路由。
- 从 `frontend/src/App.vue` 删除侧边栏“无限画布”和仅由它使用的图标导入。
- 从 `frontend/src/views/Studio.vue` 删除无限画布快捷入口、canvas 启动模式、对应弹窗状态和分支逻辑；保留 AI 创作入口。
- 从 `frontend/src/views/Tutorial.vue` 删除无限画布的使用说明，改为 AI 创作、固定顺序、素材库和编辑器路径。
- 从 `frontend/src/views/AiSettings.vue` 删除仍提到无限画布的文案，保留 Provider 媒体能力，因为 AI 创作页和媒体工具仍使用它。

### 删除画布文件与构建引用

- 删除 `frontend/src/views/InfiniteCanvas.vue`。
- 重新运行前端构建，让 Vite 自动重写 `backend/src/main/resources/static/index.html` 和 hashed assets；不手工删 hash chunk，避免 manifest 残留。
- 旧 `#/infinite-canvas` 链接采用一次性兼容重定向到 `/ai-create`，还是交给通配路由回 `/dashboard`，在实现时选择一个一致策略；不让旧入口加载已删除组件。

### 保留共享能力

不要删除以下内容：

- `frontend/src/api.js` 的 AI 图片/视频/配音提交、任务列表、任务详情、Provider 列表。
- `frontend/src/views/AiCreate.vue` 的图片、视频、配音表单和任务轮询。
- `MediaTools.vue` 使用的媒体 Provider 能力。
- `MediaGenerationController.java`、`MediaGenerationService.java`。
- `AiSettings.vue` 的 Provider、模型发现、observed/media 白名单和候选采用逻辑。
- `/api/workflows/ai-comic` 后端接口暂不删除，除非确认该接口没有其他计划使用方；先保留以避免扩大范围。

### 本地旧画布数据

- 删除前端对 `mework-infinite-canvas-draft-v2/v3`、`mework-infinite-canvas-history-*`、`mework-canvas-editor-draft` 的读取。
- 不删除素材库中已经生成的图片、视频、配音和任务记录。
- 可增加一次性前端清理旧画布 localStorage 的逻辑，或仅停止读取并在教程中说明；优先选择一次性清理但只清理这些明确键，不触碰其他草稿或用户数据。
- 删除 `AiCreate.vue` 中已经不可达的“从无限画布带入”草稿兼容逻辑和死键清理，保留 AI 创作自身草稿功能。

## 二、交接文件

新建项目根目录文件：

`Mework_PROJECT_HANDOFF.md`

文件内容使用通俗但面向开发者可执行的 Markdown，包含：

1. 应用名称、定位、用户、核心生产流程和不做什么。
2. 当前版本、实际运行端口、JAR 选择规则、前端构建到 Spring static 的链路。
3. 前端路由/页面地图和后端 Controller/Service 地图。
4. 素材导入、抓取、质量准入、预检、固定顺序、批量/持续出片、音频/字幕、QC、Outputs/Editor、AI Provider 和媒体生成链路。
5. 能力中心/环境中心/资源中心/素材源/插件接口的真实状态边界：随包可用、可修复、需 Key/账号、需模型/硬件、只打开官方入口；不把检测到伪装成已接入。
6. 安全边界：API Key 只在本机服务端密文保存；URL 仅允许 http/https；拒绝 localhost、环回、私有和保留地址；不读取 Cookie/密码；不绕过登录、DRM、付费、地区限制；自定义 Skill/插件不执行远程代码。
7. 版本历史摘要，优先列出 2.2.80 到当前版本；注明没有主项目 Git，历史依据为 release-notes、JAR、测试报告和运行接口。
8. 已完成改动、当前尚未完成项、已知风险和建议新对话优先任务。
9. 清晰的“开始继续开发”命令清单：先读哪些文件、如何构建、如何启动隔离实例、如何验证 `/api/system/env`、如何避免旧 JAR/旧静态资源混用。
10. 本次无限画布移除说明：删除了哪些入口、保留了哪些共享 AI 能力、旧链接如何处理。

文件不得包含 API Key、密码、Cookie、完整 `.env` 内容、本机访问令牌或其他凭据。

## 三、验证与版本

1. 先进行只读引用扫描，确认没有残留无限画布可达入口或误删共享 AI API。
2. 运行 `frontend npm run build` 和静态资源校验。
3. 运行后端编译及相关回归测试，重点覆盖路由、AI 创作、媒体生成、输出编辑和版本记录。
4. 启动隔离端口，验证：
   - `/api/system/env` 返回当前版本；
   - `/api/ai-generation/providers`、任务接口仍可访问；
   - `/api/jobs/outputs/all` 仍可访问；
   - `/infinite-canvas` 不再加载画布组件；
   - `/ai-create`、`/studio`、`/outputs` 正常打开。
5. 运行现有 release-notes 流程，创建下一连续补丁版本，记录无限画布移除和交接文件生成；旧历史只追加，不覆盖/删除。
6. 重新打包版本化 JAR，并同步 `mixcut-current.jar` 前先备份旧文件；生产端重启后再次校验前后端版本一致。
