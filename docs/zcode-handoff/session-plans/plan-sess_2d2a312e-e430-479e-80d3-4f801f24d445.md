## 目标
在不破坏现有“本地素材扫描入库 + FFmpeg 切片/拼接”能力的前提下，修复上传/素材选择/任务进度/渲染卡住问题，并叠加总时长驱动、文件夹隔离与跨文件夹抽取、片头替换、可选 Hyperframes、本地批量并发等能力。

## 已确认的根因
1. **上传失败提示过于粗糙**：`frontend/src/views/Materials.vue:20-23` 只绑定了 `on-success`/匿名 `on-error`，没有 `on-progress`、HTTP 状态、服务端错误、失败文件重试；多文件上传时用户无法知道哪一个失败。后端 `MaterialController.upload` 与 `MaterialService.upload` 也没有返回可诊断的上传阶段/文件大小/探测失败信息。
2. **图片“上传成功但失败”**：`MaterialService.register/updateThumbnail` 对图片缩略图生成失败会把素材状态设为 `failed`，导致 UI 看起来像上传失败；原始文件可能已经落盘。应拆分 `uploadStatus` 与 `probeStatus`，缩略图失败只显示“预览待生成”，不能让素材不可用。
3. **框选/素材选择难懂**：素材页只有 Element Plus 表格的勾选框，没有选中摘要、清空/全选/按文件夹选择、角色/文件夹上下文；Studio 的 BGM/人声只从角色列表取，无法让用户明确选择素材组。
4. **任务进度为 0%/速度为 0**：`JobService` 每条成片完成后才更新 `current/progress`；FFmpeg 的 `RenderService` 只回调步骤文字，步骤不进入任务列表落库，前端 `Studio.vue:251-260` 只显示外层任务进度，不显示当前步骤/已耗时/速度/预计剩余。默认 `app.render-pool-size=2`（`WebConfig.java:67-78` / `AppProps.java:47-52`），不能满足 20–50 并发；更重要的是 FFmpeg 启动失败、素材切片全部跳过时用户只能看到“0/5”。
5. **渲染失败的具体隐患**：`RenderService.java:73-107` 跳过失败片段但没有在任务 API 中逐段记录；`FfmpegTool.java:97-160` 的命令输出只写日志尾部，前端拿不到；`imageToClip`、字幕字体、concat、音轨均可能失败。应先做输入/输出可写性、ffmpeg/ffprobe、素材可读性预检，并记录每阶段错误。
6. **项目 schema 已包含 `folder_id`，但前端/API 没有完整文件夹管理与筛选闭环**；`MaterialController` 只列 folders，没有创建/重命名/删除/移动/按 folder 查询。

## 实施分阶段

### 阶段 A：先修复可用性与可观测性（保留现有基础能力）
#### 前端
- 修改 `frontend/src/views/Materials.vue`：
  - 使用 `el-upload` 的 `on-progress`、`on-change`、`on-success`、`on-error`，每个文件显示状态、百分比、失败原因和“重试”按钮。
  - 上传前显示文件类型/大小校验；上传后区分“文件已保存、媒体探测失败、缩略图生成失败”。
  - 增加明确的选中工具条：全选当前页、反选、清空、选中数量、按角色批量修改、按文件夹批量移动。
  - 增加文件夹树/下拉筛选、当前文件夹说明和“跨文件夹抽取”开关。
  - 预览失败时显示可读错误和重新探测按钮，而不是笼统“上传失败”。
- 修改 `frontend/src/api.js`：统一转换 Axios 错误为可显示对象，增加上传进度回调/重试封装，增加 folder/material diagnostics API。
- 修改 `frontend/src/views/Studio.vue`：
  - 任务列表增加当前步骤、最近心跳、已耗时、预计剩余、成功/失败计数、错误详情。
  - 进度条改为阶段进度：准备/切片/拼接/混音/字幕/完成；任务仍显示总体进度。
  - 干跑预览增加“按素材组查看来源”的可视化时间线，使用文字/颜色说明，不依赖用户猜框选位置。
  - 把“点击/跳转登录”从本地混剪主流程移到可选抓取页：本地模式默认不需要登录；涉及需登录平台时只提供官方页面按钮和合规开关，不把浏览器 Cookie 写入项目。

#### 后端
- 修改 `MaterialService.java` / `MaterialController.java`：
  - 上传使用安全文件名、扩展名/大小白名单、临时文件 + 原子移动；返回文件级诊断字段。
  - 将“原始文件落盘”“ffprobe 成功”“缩略图成功”拆成独立状态；缩略图失败不标记素材 `failed`，视频/图片仍可进入计划（预览显示占位）。
  - 增加 `/api/materials/{id}/reprobe`、`/api/materials/{id}/thumbnail/retry`。
  - 上传接口返回结构化错误（HTTP 状态、阶段、建议动作），支持单文件重试。
- 修改 `Job` 实体/表结构、`JobService.java`、`JobController.java`：增加 `step`、`phaseProgress`、`startedAt`、`lastHeartbeatAt`、`completedCount`、`failedCount`、`speedFps`/`speedRatio`、`etaSec`、`diagnostics`；每个 FFmpeg 阶段更新内存+低频落库，失败记录具体命令阶段和 stderr 摘要。
- 修改 `RenderService.java` / `FfmpegTool.java`：
  - 增加统一的预检：文件存在、普通文件/非符号链接、可读、输出目录可写、ffmpeg 与 ffprobe 可执行。
  - `ProcRunner` 结果分类为 timeout/non-zero/missing-output/invalid-media，并将最后一段 stderr 传回任务。
  - 不改变现有切片/concat/mux/text 流程，只增加阶段权重、耗时与错误传播；对图片和无音轨视频分别给出明确 fallback。
- 迁移 `schema.sql`/新增 migration：幂等添加上述 job 字段及必要索引。

### 阶段 B：数据结构与素材组能力
- 保留 `material_folder` 与 `material.folder_id`，新增/完善：
  - `folder_type`（hook/body/celebrity/product/voice/bgm/endcard/custom）、`parent_id`（可选）、`sort_order`、`enabled`；material 增加 `probe_status`、`thumbnail_status`、`last_error`。
  - `intro_profile`/`intro_clip` 表（或在 workflow/project JSON 中引用）保存可替换片头、启用状态、默认时长、素材 ID。
  - `workflow_material_rule`（workflow/project + role + folder + min/max/weight）保存人工预先整理的分组规则，避免完全交给 AI 自由拼接。
- 新增后端接口：
  - `GET/POST/PUT/DELETE /api/material-folders`（列表、创建、重命名、启停、删除空文件夹）；
  - `POST /api/materials/{id}/move`、`POST /api/materials/batch-move`；
  - `GET /api/materials?folderId=...&includeChildren=...`；
  - `GET/POST/PUT/DELETE /api/intro-clips`；
  - `GET/PUT /api/workflows/{id}/material-rules`；
  - `GET /api/jobs/{id}/events`（阶段事件/失败诊断，前端可轮询；先不引入 WebSocket，降低本地部署复杂度）。
- 所有查询参数使用 Spring 参数绑定/Repository 查询方法或参数化 JPQL，禁止字符串拼接 SQL；外部 URL 若保留抓取能力，只允许 `http/https` 并在请求前拒绝 localhost、环回、私有和保留地址。

### 阶段 C：总时长驱动与人工可控混剪
- 扩展 `MixParams.java`：
  - `targetDurationSec`（必填时优先于区间）、`durationAllocationMode`（equal/random-weighted/manual）、`randomSeed`、`minSegmentSec`、`maxSegmentSec`；保留现有 `minSec/maxSec/sliceSec/sliceJitter` 兼容旧参数。
  - `materialSelectionMode`（rules-only/rules-plus-cross-folder）、`folderIds`、`roleFolderRules`、`introClipId`、`introEnabled`、`introDurationSec`。
- 扩展 `MixPlanner.java`：
  - 先扣除片头/片尾，再按人工规则分配目标总时长；均等模式按段数平均，随机模式用 seeded random 在 min/max 约束内分配，最后做总和校正。
  - 角色段优先从预设 folder/rule 取；跨文件夹模式只在同角色候选组内随机抽取，禁止无约束跨角色乱配。
  - 片头作为固定第一段，随时替换只改变规则引用，不破坏旧计划。
  - 预览返回每段 `folderName/role/sourceStart/duration/reason`，UI 可解释“为什么选它”。

### 阶段 D：批量并发与本地队列
- `AppProps` / `application.yml` 增加 `render-pool-size` 默认可配置 2，允许安全范围 1–50；`render-queue-capacity`、每任务 CPU/内存保护、单机最大同时 FFmpeg 数量。
- `WebConfig.renderExecutor` 使用有界队列和明确拒绝/排队响应；默认不盲设 50，UI 提供 2/4/8/16/32/50，并根据 CPU 核数提示推荐值。20–50 是上限能力，不代表任何机器都适合同时运行 50 个 FFmpeg。
- `JobService` 保留现有恢复检查点和 watchdog，改为每个输出成功/失败立即更新计数；增加取消时对外部 FFmpeg 进程的可控终止句柄，避免“取消后仍占资源”。
- 任务 API 返回队列位置、并发上限、活跃数、预计等待时间；前端展示“排队/运行/完成/失败”四类清晰状态。

### 阶段 E：可选 Hyperframes 片头模块
- 将现有 `tools/hyperframes-upstream` 作为可选子模块，不放进默认本地渲染链。
- 增加 `HyperframesService` 与 `/api/intro-clips/generate`：仅接收本地输入、模板/参数，生成 mp4 后登记为 `intro_clip`；生成失败不影响普通 FFmpeg 混剪。
- UI 增加“启用 Hyperframes 片头”开关、生成状态、替换/预览/禁用按钮；默认关闭，避免额外依赖与成本。

### 阶段 F：构建、回归与验收
- 前端：`npm ci`/`npm run build`；检查上传进度、失败重试、文件夹筛选、干跑解释、任务实时进度。
- 后端：`mvn test`、`mvn package -DskipTests`；增加单测覆盖时长分配、文件夹规则、片头首段、失败状态传播、并发上限。
- 本地运行验证：用真实小图片/视频/音频分别上传，确认单文件失败不影响其他文件；提交 1/5/20 条任务，观察阶段进度、速度、ETA、失败详情和恢复。
- 使用浏览器黑盒验证 `/materials`、`/studio`、`/workflows`，确认界面不再出现“框选位置不明”“0/5 无说明”。
- 最终输出：修改点、数据结构、完整新增/修改文件路径、接口清单、构建与实测结果、仍需用户提供的素材/AI Key（若有）。
