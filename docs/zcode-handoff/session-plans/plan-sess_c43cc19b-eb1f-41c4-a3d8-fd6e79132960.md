## 目标
把现有 MoneyPrinterTurbo 从“临时按主题生成”整理为可长期复用的本地产品混剪环境，减少每条视频的冷启动、在线素材下载和重复配置时间。

## 已确认现状
- 项目已在 `C:\Users\Windows\MoneyPrinterTurbo`，包含可用的 Python 3.11 虚拟环境、主要依赖、FFmpeg、中文字体、BGM、在线素材缓存和已有成片。
- 现有 Skill 的标准调用默认走在线 Pexels 素材，且明确禁止并行运行多个视频任务。
- 项目本体支持本地素材模式，但现有 Skill 没有把本地素材参数传递给项目 CLI；这正是产品混剪速度与素材一致性的主要缺口。
- 本地 Whisper 模型尚未下载；它只在需要音频转录字幕时才有必要，默认不预下载体积较大的模型。

## 实施步骤
1. **稳定运行入口**
   - 确认 `uv` 可从后续命令会话直接调用；若 PATH 未持久生效，添加用户级 PATH 项。
   - 保留现有项目虚拟环境和依赖锁定状态，不重装已经可用的核心依赖。
   - 检查项目内置 FFmpeg 可用，并让后续流程优先复用它而非每次寻找系统级 FFmpeg。

2. **建立本地产品素材库**
   - 创建 `C:\Users\Windows\MoneyPrinterTurbo\storage\local_videos` 作为项目受控的本地素材库，以及 `incoming`、`processed`、`output` 等清晰目录。
   - 放置一份文件夹模板和说明文档：每个产品应包含原始视频、图片、Logo、卖点/禁用词、目标时长和风格要求。
   - 用本地素材优先策略避免每个任务再下载 Pexels 素材，也避免项目在生成时从项目外复制大文件。

3. **为产品混剪扩展 Skill**
   - 在 ZCode、Codex 和共享 `.agents` 的 MoneyPrinterTurbo Skill 中加入统一的“本地产品素材混剪”调用约定。
   - 让 Skill/辅助脚本能接收产品素材目录、固定文案（可选）、视频时长、9:16 画幅、顺序拼接/混剪策略和线程数，并安全转换为已验证的项目 CLI 参数。
   - 保持默认主题生成功能不变；只有用户明确给出本地素材目录时才启用本地素材模式。
   - 不将任何 API Key 写入 Skill 文档、模板或日志。

4. **创建快速产品混剪模板**
   - 提供默认 30 秒竖屏结构：`3 秒钩子 → 3 个卖点 → 产品特写 → 行动引导`。
   - 默认沿用现成中文语音、字幕样式和背景音乐；支持从每个产品文件夹覆盖文案与卖点。
   - 设置适度的 FFmpeg 线程数，优先让单任务渲染更快，同时保留系统响应能力。

5. **多任务处理方式**
   - 增加一个本地任务清单/队列脚本：可一次提交多个产品文件夹，并按受控顺序执行。
   - 默认**串行执行**，符合官方 Skill 不并发生成的限制，避免多条渲染抢占 CPU、磁盘和网络后整体更慢或失败。
   - 队列会为每个任务单独保存输出目录和简明状态；失败任务保留错误信息，不会影响后续排队任务。
   - 如后续需要真正并发，会先进行硬件编码和资源占用实测，再单独启用有限并行，而不是直接开多任务。

6. **验证与交付**
   - 用一个不包含敏感密钥的本地示例素材目录做参数校验和干运行检查；不额外生成一条可能耗时数分钟的成片，除非你明确要求。
   - 最后给你一份简短中文使用说明：老板素材如何放、如何让 ZCode/Codex 批量做混剪、输出文件在哪，以及速度预期。

## 不会做的事
- 不会打印、复制或提交你已提供的 API Key。
- 不会预下载大型 Whisper 模型，除非你确认今后必须使用本地音频转写字幕。
- 不会在没有测试硬件资源的情况下开启并发视频渲染。

## 预期结果
后续给一个按模板整理好的产品素材文件夹时，可跳过首次安装、依赖准备和在线素材抓取；常规 20–40 秒产品混剪会以本地文件读写和渲染为主，通常明显快于这次首次端到端生成。
