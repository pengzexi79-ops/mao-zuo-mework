## 目标与边界
继续在现有项目 `<legacy-workspace>\ai-douyin-mixcut` 上开发，不重写已验证的 FFmpeg 混剪主流程。此次交付分为：图片全链路修复、本机工具链与隔离目录、Hyperframes 可选动画增强、Remotion 可选评估渲染器、GitHub+Google Trends 公开趋势雷达、剪映导出交接包。

明确安全边界：不读取浏览器 Cookie、不自动登录、不绕过反爬或访问控制；趋势内容只做公开数据线索和人工确认下载；剪映不做默认桌面自动操控，只生成用户可手动导入的交接包。Hyperframes 只在 Skill DSL 校验完成且任务明确需要动画时运行；它只生成 MP4 片段，后续仍由原有 FFmpeg 切片、拼接、音频和字幕链路处理。

## 1. 修复图片素材全链路（最高优先级）
涉及 `MaterialService.java`、`MaterialController.java`、`WebConfig.java`、`Materials.vue`、`Studio.vue`、`Outputs.vue`、`FfmpegTool.java` 与 DTO/API。

- 图片导入/扫描也执行 ffprobe，保存宽高、可用状态和默认显示时长（建议 3 秒）；不再让图片的媒体元数据全为空。
- 图片格式校验覆盖 JPG/PNG/透明 PNG/WebP/BMP；预览/渲染时处理 EXIF 方向，避免手机竖图横向显示。
- 为已登记素材增加安全的 `GET /api/materials/{id}/preview`：只读数据库中已登记且真实存在的图片/视频文件，拒绝目录、符号链接越界、非登记路径和非媒体类型；沿用现有令牌保护与正确 MIME。
- 增加统一 `previewUrl`/`thumbnailUrl` 返回字段；前端不再只取文件名拼 `/files/thumbs/...`，避免外部目录、同名文件、中文路径造成碰撞。
- 图片生成缩略图失败要进入可见状态/错误提示，而不是静默吞异常。
- `Materials.vue` 增加图片真实缩略图、加载失败提示和预览弹窗；视频可播放、音频显示播放器/元信息。Studio/Outputs 使用后端资源 URL。
- 保持 `MixPlanner` 图片 Segment 独立对象和现有 variant/3 秒切片/产品均匀插入规则；`FfmpegTool.imageToClip` 作为图片→普通 MP4 的唯一主流程。
- 使用 JPG、PNG、透明 PNG、WebP、EXIF 旋转、中文路径、外部目录和同名图片进行验收；至少渲染一条含图片+视频+BGM+字幕的成片。

## 2. 本机工程环境与工具隔离
- 只读检查当前 Node/npm/Git/JDK/Maven/FFmpeg/ffprobe/MySQL/yt-dlp/Git LFS 版本和路径；已有工具不重复安装。
- 使用项目内 `tools/` 或 `.toolchain/` 保存第三方仓库/Node worker，不污染 Java 源码与素材目录。
- FFmpeg 保持现有 `app.ffmpeg`/`app.ffprobe` 单一配置入口，记录 Windows 构建来源、版本和 LGPL/GPL 组合。
- yt-dlp 继续作为公开/授权 URL 的可选抓取器，默认不读取浏览器 Cookie；启动自检显示版本与可用状态。
- 增加 `tools/README.md`、环境变量说明和卸载方式；忽略 node_modules、第三方仓库、二进制、缓存和渲染输出。

## 3. Hyperframes 可选增强模块
目标仓库：`https://github.com/heygen-com/hyperframes`。已核验信息：Apache-2.0；官方 README 要求 Node.js 22+ 与 FFmpeg；CLI 支持 init/preview/lint/check/snapshot/render 等；输出确定性 MP4；底层使用 headless Chrome/Puppeteer/FFmpeg。官方没有承诺完整 Windows 矩阵，因此先在本机隔离环境验证。

- 在 `tools/hyperframes-worker/` 建独立 Node 项目，不把 Node 依赖放进 Spring Boot。
- worker 接收严格 JSON：任务 ID、模板名、文本、颜色、尺寸、fps、时长、输出路径；只允许预注册模板/白名单字段。
- 用参数数组调用 Hyperframes CLI/API，禁止 shell 字符串拼接；增加输出目录白名单、最大时长/尺寸/文件大小、超时、进程树清理、尾日志和幂等任务 ID。
- 在 Skill DSL 解析完成后检查 `animation.enabled` 或内置动画 Skill：无动画直接跳过；有片头/动态字幕/图文动画先生成 MP4，ffprobe 验证后作为 generated/普通素材交给现有 RenderService。
- Hyperframes 失败默认回退无动画主流程，不让任务卡 pending；记录 `animationSkipped`、`animationRendered`、`animationFallback`。
- 首期只提供片头标题卡、动态卖点字幕卡、产品参数图卡；不开放任意 HTML/JS/命令模板。

## 4. Remotion 可选评估渲染器
- Remotion 独立 Node worker 与 Hyperframes 并列，不替代主流程；先核验实际版本、许可证/商业条款和 Windows 运行条件。
- 若条件通过，建立最小 React composition，Java 通过受控 JSON/本地进程协议调用；输出 MP4 后交给 FFmpeg。
- 增加 renderer adapter：`none`、`hyperframes`、`remotion`；若许可证/运行条件无法确认，默认 disabled，仅保留可复现安装说明，不影响主链路。

## 5. GitHub + Google Trends 公开趋势雷达
- 新增 `TrendController`、`TrendService`、公开趋势 DTO 和前端趋势/开源工具页面或 Dashboard 入口。
- GitHub 使用公开 Search/Trending/RSS 线索，展示关键词、Stars/Forks、更新时间、许可证、来源链接；可选 `GITHUB_TOKEN` 仅提高公开 API 配额，不读取私人仓库。
- Google Trends 使用可公开访问页面/RSS/用户关键词；不宣称稳定的官方免费 API，遇限流明确显示不可用；缓存关键词、地区、查询时间、来源和缓存时间。
- 趋势结果只用于选题和 Hook/Skill 建议，不自动复制热门视频；下载必须人工确认并复用现有公开 URL/SSRF 校验。
- 增加请求节流、缓存、来源/许可证字段和人工审核状态；不把“爆火”当作未经验证事实。

## 6. 剪映导出交接包
- 不自动操控剪映内部素材库、时间线、模板、登录态或私有格式。
- 新增“导出剪映交接包”：最终 MP4、封面、SRT/字幕文本、素材清单 CSV/JSON、时间线摘要、BGM/音效来源与许可证说明。
- 交接包不包含 API Key/Cookie；文件名和路径遵守 Windows 安全规则；交接包失败不影响已经生成的 MP4。
- 前端提供导出按钮和手动导入剪映说明。
