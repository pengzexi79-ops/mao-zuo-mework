在 `D:\zcode\projects\minecraft-demo` 创建一个独立、无构建依赖的静态网页示范，包含 `index.html`、`style.css`、`script.js`，不修改现有猫作或 MoneyPrinterTurbo 项目。

**页面定位**

做成“我的世界轻量化配置工作台”，不是营销落地页。核心体验是：用户选择设备/画质档位，查看当前性能状态，按风险可控地应用轻量化方案，并通过像素世界预览看到设置变化。

**界面结构**

1. 顶部应用壳
   - 品牌标题“轻量化工作台”与当前配置标签。
   - 页面级状态：已同步、待应用、低风险提示。
   - 主导航只保留“概览、配置档、性能诊断”三个任务入口。

2. 首屏工作台
   - 左侧主面板：自绘像素风 Minecraft-inspired 场景预览，使用 Canvas/CSS 绘制方块地形、天空、树和光照，不依赖外部图片或官方资源。
   - 右侧配置面板：配置档选择（省电/均衡/流畅）、内存滑块、渲染距离滑块、粒子/阴影/动画开关。
   - 主操作只有“应用轻量化配置”，次要操作为“恢复默认”。
   - 所有控件具有稳定尺寸、明确标签和实时状态反馈。

3. 性能概览区
   - FPS、内存占用、加载时间、渲染负载四个指标。
   - 通过配置变更实时更新数值和状态颜色，体现状态模型，而不是静态装饰。
   - 显示“预计改善”摘要，避免把所有说明文字堆在首屏。

4. 诊断与建议区
   - 三张紧凑诊断项：渲染距离、资源包、后台负载。
   - 每项有状态、原因和一个明确的处理动作。
   - 折叠式“详细说明”承载次要文字，减少工作台杂乱。

5. 底部运行状态栏
   - 显示当前配置、应用进度、最近操作。
   - 应用配置时模拟可取消的短暂进度状态，完成后变为已应用；失败/恢复默认都有可见反馈。

**交互与状态逻辑**

- 配置档切换会更新相关滑块和开关，并同步性能指标。
- 手动调整任意控件后进入“待应用”状态。
- 点击应用后进入 applying 状态，按钮禁用、显示进度，完成后进入 applied。
- 恢复默认会回到 balanced 基线，并清空待应用状态。
- 配置状态、诊断状态和操作状态分开管理，避免一个布尔值控制整个页面。
- 使用 aria-label、键盘可操作控件、可见 focus 状态和 `aria-live` 状态播报。
- 用 `prefers-reduced-motion` 禁用或降低过渡动效。

**视觉方向**

- 深色夜间工作台，像素世界场景作为第一视觉信号。
- 绿色草地、青色水面、暖黄色灯光和暗灰 UI 面板，避免单一紫色渐变。
- 8px 以下圆角、1px 边框、紧凑信息密度、明显但克制的状态色。
- 标题、数值、辅助文字、标签建立清晰层级；不使用大段说明性文字。
- 桌面三栏/双栏布局，窄屏时改为单列，保证控件和文字不重叠。

**实现与验证**

1. 创建 HTML 结构、CSS token、响应式布局和 Canvas 场景。
2. 添加纯 JavaScript 状态模型、配置档、滑块/开关绑定、性能计算和应用流程。
3. 添加 reduced-motion、键盘焦点、aria-live 和错误/恢复反馈。
4. 使用 `python -m http.server` 启动静态服务，避免直接打开文件时出现模块或路径限制。
5. 用浏览器黑盒交互验证：切换档位、调节滑块、应用配置、恢复默认、折叠诊断项、移动端布局。
6. 截取桌面与窄屏视图，检查 Canvas 非空、文字不溢出、控件不重叠、状态变化可见。
7. 完成后提供本地 URL 和项目目录；不接入外部 CDN，不安装 npm 依赖。
